# Deterministic baselines -- corrected costs (folds 1-3)

> Corrected accounting (audit defects #8 slippage units, #9 regime look-ahead). Eval-only, deterministic, single value per cell (no seeds). Fold 4 never loaded. Generated by `run_baselines_corrected.py`; raw rows in `results/r2/corrected/baselines_corrected.csv`. Old values: `results/baselines/baselines_results.csv` (frozen 2026-08-05, **defective costs**).

- The 7 baselines are `run_baselines.build_strategies` unchanged (unshielded; each runs its own rebalance rule, no smoothing / band / cadence from the RL execution layer). Only change in procedure: env regime thresholds calibrated on each fold's training slice, as the #9 fix requires.
- **ew_matched_execution** (new, no old value): constant 0.2-per-asset target through the RL agents' canonical execution layer (smoothing β 0.1, band 0.10, 5-day decisions, gross cap 2.0). Starting flat, smoothing needs ~7 decisions (~35 trading days) before the target clears the band.
- cost/NAV = sum of daily transaction cost / NAV; gross P&L = frictionless replay of held weights. The old file has neither column.

## Notes

- `hmm_regime` fold 1: the HMM fit fails ('covars' must be symmetric, positive-definite), so the strategy falls back to equal-weight monthly -- identical to `equal_weight_monthly` in both old and new runs. hmmlearn 'Model is not converging' warnings on stderr during the other folds' fits are benign.
- `equal_weight_k5_band010` fold 2 is bit-identical old vs new: in that window the band never triggers after the day-0 purchase (cost/NAV = 0.0035 = the day-0 rate, which the #8 defect did not affect), so the cost defect never bit.
- Turnover is essentially unchanged old vs new for every strategy (rules are price-driven, not cost-driven); the return differences are the cost correction (plus, negligibly, the #9 env change, which no baseline reads).
